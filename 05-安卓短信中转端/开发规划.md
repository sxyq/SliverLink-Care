# 安卓短信中转端开发规划

## 1. 当前结论

安卓端已经从“第一版可编译原型”推进到“可安装、可后台运行、可真机联调”的阶段。

当前最重要的变化是：

- 主链路已经切到前台常驻服务
- 短信接收后可以直接在后台完成解析与上传
- 运行时权限、配置同步、息屏保活和服务状态展示都已接入

## 2. 当前已落地能力

### 基础工程

- Android Gradle Wrapper 可用
- `app` 模块可构建、可安装
- Debug APK 可输出

### 业务链路

- 监听 `SMS_RECEIVED`
- 使用 `SmsParser` 过滤短信前缀与验证码格式
- 通过 `SmsRelayRepository` 回传原始短信记录
- 通过 `RelayApiService` 上报心跳、拉取配置
- 为请求附加设备签名

### 后台运行

- `RelayForegroundService` 常驻
- `MainActivity` 启动时拉起服务
- `BootCompletedReceiver` 重启后恢复服务
- 服务内固定 15 分钟心跳
- 短信上传和心跳发送阶段持有短时 `PARTIAL_WAKE_LOCK`
- 设置页支持系统电池优化白名单跳转

### 用户界面

- 总览页展示设备在线与后台服务状态
- 记录页展示短信上传记录
- 设置页支持配置保存、权限申请、服务端同步、息屏保活查看

### 测试与验证

- 单元测试已覆盖：
  - `SmsParser`
  - `RelayRequestSigner`
  - `RelayConfigSyncResolver`
- 仪器测试已提供 `MainActivitySmokeTest`
- 真机已验证：
  - 应用可启动
  - 前台服务可启动
  - 息屏后服务仍在运行

## 4. 关键设计取舍

### 4.1 为什么保留 Worker

当前上传主路径已经是前台服务，但 `InboundSmsUploadWorker` 和 `HeartbeatWorker` 没有立即删除，原因是：

- 仍可作为兜底重试路径
- 后续可以继续承接异常恢复
- 便于逐步从原先 Worker 模式平滑过渡

### 4.2 为什么新增服务状态持久化

服务运行状态不仅显示在通知栏，还会写入本地偏好，用于：

- 总览页展示“后台服务已运行”
- 设置页展示更清晰的运行状态
- 应用重开后快速恢复上次状态提示

### 4.3 为什么加入电池优化白名单引导

单纯前台服务在部分国产 ROM 上仍可能被限制，因此增加：

- 电池优化状态检测
- 一键打开系统设置
- 真机侧系统白名单验证

## 5. 当前剩余工作

### 高优先级

- 做一轮真实短信闭环留档：
  - 用户发送真实短信
  - 安卓端收到并上传
  - 统一后端记录生成
  - 后台页面可见

### 中优先级

- 补 Worker 自定义退避策略
- 增加更多失败原因展示
- 增强服务异常恢复提示

### 低优先级

- 补更完整的仪器测试
- 补更系统的多机部署与运维说明

## 6. 当前验收口径

安卓端阶段性完成以这几条为准：

- `testDebugUnitTest` 通过
- `installDebug` 通过
- 真机能启动应用
- 真机能看到后台服务状态
- 真机息屏后服务仍在运行
- 能成功对统一后端发送心跳

完整业务完成则再加一条：

- 真实短信闭环验证完成并留档
