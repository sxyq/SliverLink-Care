# 微信接入与发布流程

本文档已按当前项目现状写死关键环境信息：

- 正式域名：`https://sxyq27.online`
- 小程序接口基地址：`https://sxyq27.online/silverlink-api`
- 线上 H5 参考入口：`https://sxyq27.online/silverlink/scan/`
- 线上工作台参考入口：`https://sxyq27.online/silverlink/volunteer/`
- 部署宿主机：`124.222.153.108`

注意：

- 微信公众平台里填写域名时，只填域名，不填服务器 IP
- 当前服务器信息只用于你确认部署归属，微信侧一律配置 `https` 域名

## 零、当前开发硬边界

从当前阶段开始，小程序开发必须遵守下面这条硬边界：

- `04-统一后端` 视为冻结，不作为小程序联调阶段的改动对象
- 线上后端现有接口路径、请求方式、响应结构、Cookie 会话语义，全部按既成事实接入
- 小程序侧如遇到登录态、参数、下载、扫码、角色分流问题，优先通过小程序前端适配解决
- 不允许因为小程序开发便利性，反向要求修改后端接口、鉴权方式或返回结构

尤其要默认接受下面两点：

- 志愿者 / 管理类能力可能依赖后端 `Cookie Session`
- 不同角色接口的登录态语义可能不完全一致，小程序侧必须按真实线上行为分别适配

如果后续确实发现后端存在阻断级缺陷，也只能先在文档中记录“受后端现状约束”，不能直接把“小程序需要改后端”当默认方案。

## 一、准备项

在开始前，你需要先准备好：

1. 微信公众平台中的小程序账号
2. 该小程序的 `AppID`
3. 已备案且可访问的正式业务域名
4. 可用于小程序请求的 `HTTPS` 接口地址
5. 小程序管理员或开发者权限
6. 审核测试账号与审核路径说明
7. 小程序头像、名称、介绍、隐私政策

当前这套工程里已经可以直接复用的线上参数是：

- `request` 合法域名：`https://sxyq27.online`
- `downloadFile` 合法域名：`https://sxyq27.online`

原因：

- 代码里的请求地址虽然是 `https://sxyq27.online/silverlink-api`
- 但微信配置时只能按域名维度填写，所以填写主域名 `https://sxyq27.online` 即可

## 二、绑定 AppID

### 方式一：新建项目时绑定

1. 打开微信开发者工具
2. 使用管理员或开发者微信扫码登录
3. 点击 `小程序`
4. 选择 `导入项目` 或 `新建项目`
5. 项目目录选择本地 `08-微信小程序端`
6. 在 `AppID` 输入框填入微信公众平台对应小程序的 `AppID`
7. 项目名称填：`智联名牌`
8. 后端服务选择 `不使用云服务` 或按实际情况选择
9. 完成后工具会把该 `AppID` 与本地项目关联

### 方式二：通过配置文件绑定

在微信开发者工具识别的项目根目录放置 `project.config.json`，其中写入：

```json
{
  "appid": "你的小程序AppID",
  "projectname": "智联名牌",
  "miniprogramRoot": "dist",
  "compileType": "miniprogram"
}
```

本目录已提供示例文件：

- `project.config.json.example`

当前仓库中的 `project.config.json` 已写入当前 `AppID`：

- `wxd6f1eb971f5d4bc5`

建议同步检查：

- `projectname`：保持 `智联名牌`
- `miniprogramRoot`：保持 `dist`
- `compileType`：保持 `miniprogram`

## 三、导入微信开发者工具

推荐流程：

1. 先在本地执行构建，把可上传产物输出到 `dist`
2. 打开微信开发者工具
3. 选择 `导入项目`
4. 目录指向 `08-微信小程序端`
5. 工具读取 `project.config.json`
6. 完成后点击 `编译`
7. 在模拟器和真机预览中检查首页、扫码、登录、角色分流是否正常（提审/发布前运行时检查，不属于当前代码层单元、性能、安全测试完成条件）

建议先在本地执行：

```bash
cd /Users/sunyiyang/Desktop/Project/SilverLink\ Care/08-微信小程序端
npm run typecheck
npm run build:weapp
```

这两步通过后，再导入微信开发者工具会更稳。

## 四、服务器域名配置

在微信公众平台：

1. 进入对应小程序后台
2. 打开 `开发` -> `开发设置`
3. 配置服务器域名

至少要补：

- `request` 合法域名
- `downloadFile` 合法域名
- 如有 WebSocket，再补 `socket` 合法域名

当前项目建议填写：

| 配置项 | 建议值 |
| --- | --- |
| `request` 合法域名 | `https://sxyq27.online` |
| `downloadFile` 合法域名 | `https://sxyq27.online` |
| `uploadFile` 合法域名 | 当前无必填，如后续补上传再加 |
| `socket` 合法域名 | 当前未接入，可留空 |

注意：

- 只能使用 `https`
- 不能直接填 IP
- 域名必须已备案
- 小程序正式请求时必须通过证书校验

当前代码依赖这些线上能力：

- 登录、档案、用药、量表、二维码接口请求
- 名牌 PDF 下载
- 志愿者端 Cookie 会话维持

所以 `request` 和 `downloadFile` 两项必须先配置正确，否则真机侧会直接失败。

## 五、当前代码对应的审核演示路径

建议审核时只讲两条主路径，口径最清晰：

### 路径 A：扫码查看

1. 打开首页
2. 点击 `扫码查看`
3. 进入扫码落地或验证链路
4. 查看老人基础档案、用药、量表等只读信息

说明：

- 当前扫码主链路代码已收口，审核时建议优先准备稳定可演示的码和账户
- 若审核主要看小程序首页结构与查看能力，可以先聚焦首页与验证后的查看结果

### 路径 B：志愿者 / 家属工作台

1. 打开首页
2. 点击 `志愿者 / 家属登录`
3. 输入审核账号登录
4. 自动按角色进入老人列表
5. 打开老人详情
6. 演示基本信息、用药、量表、二维码、名牌 PDF

当前代码里的真实业务差异：

- 志愿者登录依赖后端 Cookie 会话
- 家属登录同时返回 Token 与 Cookie
- 志愿者可编辑更多老人信息
- 家属当前只维护联系人和自己权限内的用药、二维码能力
- 家属量表页当前未开放

这里再强调一次：

- 上述差异全部按后端当前真实行为接入
- 小程序端只能做兼容和适配，不能以统一体验为理由要求后端改协议

## 六、上传代码

完成联调后，在微信开发者工具中：

1. 点击 `上传`
2. 填写版本号
3. 填写项目备注
4. 确认上传

建议版本规范：

- `0.1.0`：首个提审版
- `0.1.1`：审核修订版
- `0.2.0`：新增统一工作台版

建议备注规范：

- `首版提审：首页+扫码查看`
- `补充：志愿者家属统一登录`
- `修复：扫码验证与导出`

建议当前首个上传备注可写：

- `首版提审：首页双入口、统一登录、老人详情、二维码与名牌导出`

## 七、提交审核与发布

代码上传成功后：

1. 登录微信公众平台
2. 进入对应小程序后台
3. 选择已上传版本

5. 提交审核
6. 审核通过后点击发布

## 八、审核说明建议

首版建议只提这两个入口：

1. 首页 `扫码查看`
2. 首页 `志愿者 / 家属登录`

审核说明建议写清：

- 扫码用于查看老人基础档案信息
- 志愿者与家属共用统一工作台
- 家属和志愿者靠账号角色区分权限
- 不提供医疗诊断，仅做信息展示和照护记录

建议再补一句：

- 实体卡扫码与小程序内查看都围绕同一位老人档案展开，用于家属与照护协同

如果要填写测试说明，可优先按下面口径整理：

| 项目 | 建议填写 |
| --- | --- |
| 首页主入口 | `扫码查看`、`志愿者 / 家属登录` |
| 核心功能 | 老人基础信息查看、用药记录维护、量表查看、二维码与名牌导出 |
| 账号角色 | 志愿者、家属 |
| 风险说明 | 不提供在线问诊、支付、社交发布等能力 |

1. `AppID` 是否绑定正确
2. 首页文案、头像、名称是否与备案一致
3. 域名是否全部为 `https`
4. 是否已配置隐私政策与用户隐私保护指引
5. 是否准备好审核测试账号
6. 是否准备好审核路径说明
7. 是否准备好异常页和空态页
8. 是否已在真机验证 `下载 PDF -> 打开文档`（发布前运行时项）
9. 是否已验证志愿者登录 Cookie 会话在真机可用（发布前运行时项）
10. 是否已验证家属登录后的角色分流正确（发布前运行时项）
