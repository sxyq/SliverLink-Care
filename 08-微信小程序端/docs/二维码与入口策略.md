# 二维码与入口策略

本文件用于把当前已经确定的小程序入口方案单独写清楚，避免后续开发时再次混淆：

1. `普通 H5 二维码`
2. `微信小程序码`
3. `首页扫码入口`
4. `登录后工作台入口`

## 一、最终采用的方案

当前项目采用“双入口、双码”的稳定方案，而不是“单二维码自动识别分流”方案。

### 1. 通用二维码

- 类型：`H5 二维码`
- 目标：所有扫码器、手机相机、非微信环境都能打开
- 入口地址：正式 `https://` 页面
- 典型页面：扫码公开查看页、老人公开基础信息页

### 2. 微信二维码

- 类型：`微信小程序码`
- 目标：微信扫一扫后直达小程序页面
- 入口方式：`scene`、`page`、`path`
- 典型页面：`scan/landing`、`scan/verify`、`workbench/elder-detail`

### 3. 小程序首页

首页只保留两个主入口：

- `扫码查看`
- `志愿者 / 家属登录`

不在首页继续扩散更多入口，避免审核和真实用户使用时都变复杂。

## 二、当前不采用的方案

以下方案当前不作为项目正式方案：

- 一个普通二维码根据扫码方式自动分流到 H5 或小程序
- 依赖 `URL Scheme / URL Link` 的个人主体唤起链路
- 让小程序码兼任普通网页二维码
- 把扫码入口和登录工作台入口塞成同一个复杂首页流

原因：

- 个人主体能力边界不稳定
- 审核与平台限制风险较高
- 线下实体卡要求优先保证“任何设备都能打开”

## 三、参数统一原则

无论是 H5 二维码还是小程序码，最终都应该定位到同一个业务对象。

统一目标字段建议：

- `qrToken`
- `elderId`
- `archiveNo`
- `inviteCode`

建议优先级：

1. 优先使用后端下发的短时 `qrToken`
2. 不直接裸露敏感身份字段
3. 页面侧通过解析参数再向后端换取可展示数据

## 四、H5 二维码策略

### 用途

- 实体卡主二维码
- 打印物主二维码
- 非微信环境主入口

### 建议承载地址

- `https://sxyq27.online/silverlink/scan/`
- 或具体公开查询页地址

### 页面职责

- 展示基础信息
- 引导做短信验证或身份登记验证
- 验证后查看健康档案、用药、量表、名牌

## 五、小程序码策略

### 用途

- 微信专属直达入口
- 社群传播或公众号内容中的微信体验入口
- 审核演示路径中的扫码直达入口

### 建议直达页

- `src/subpackages/scan/landing/index.tsx`
- `src/subpackages/scan/verify/index.tsx`
- `src/subpackages/workbench/elder-detail/index.tsx`

### 参数规则

#### 方案 A：`page + scene`

适用：不限制小程序码

- `page`: 指向固定页面
- `scene`: 承载业务标识

示例语义：

- `page = subpackages/scan/landing/index`
- `scene = qrToken=xxx`

#### 方案 B：`path`

适用：小程序码或小程序二维码

- `path`: 直接携带页面与查询参数

示例语义：

- `subpackages/scan/landing/index?qrToken=xxx`

## 六、代码目录中的对应关系

### 页面

- `src/pages/home/index.tsx`
  - 首页两个主入口
- `src/subpackages/scan/landing/index.tsx`
  - H5 同源业务在小程序中的扫码落地页
- `src/subpackages/scan/verify/index.tsx`
  - 验证页
- `src/subpackages/workbench/qrcode/index.tsx`
  - 工作台二维码与名牌管理页

### hooks

- `src/hooks/useAppLaunch.ts`
  - 解析普通启动、小程序码启动、扫码启动
- `src/hooks/useScanEntry.ts`
  - 首页主动扫码入口

### services

- `src/services/scan/scanAuthService.ts`
  - 扫码解析、短时访问授权
- `src/services/workbench/qrcodeService.ts`
  - 工作台端二维码、小程序码、名牌导出能力

### utils

- `src/utils/routeParams.ts`
  - 统一解析 `scene / path / query`

## 七、后续开发时必须遵守的边界

### 可以复用

- 现有二维码业务字段语义
- 现有档案查看流程
- 现有验证流程
- 现有名牌导出规则

### 不能直接复用

- H5 复制链接逻辑
- 浏览器下载 PDF 逻辑
- 浏览器地址栏参数解析
- H5 hash 路由直达方式

## 八、推荐开发顺序

1. 先完成 `scan/landing` 参数解析
2. 再完成 `scan/verify`
3. 再完成 `workbench/qrcode`
4. 最后补小程序码申请、展示、刷新、停用的后台联动
