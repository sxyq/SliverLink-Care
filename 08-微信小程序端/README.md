# 智联名牌微信小程序端

本目录用于承载“单小程序方案”的微信小程序工程。

当前规划目标：

- 一个小程序同时承载 `扫码查看` 与 `志愿者 / 家属工作台`
- 首页只保留两个主入口
- 志愿者与家属共用同一套工作台页面，登录后根据账号角色分流
- 扫码端支持首页点击扫码，也支持实体卡直接拉起到扫码查看页
- 微信场景使用 `小程序码` 直达小程序页面，通用场景继续使用 `H5 二维码`

## 推荐技术路线

- 框架：`React + Taro`
- 语言：`TypeScript`
- 样式：`SCSS` 或 `CSS Modules`
- 状态：优先本地状态，必要时再补轻量全局状态
- 接口：复用 `04-统一后端`

当前阶段先落目录规划和接入文档，不直接引入脚手架依赖，避免覆盖你现有仓库结构。

## 核心开发原则

### 1. 最大程度复用旧代码

小程序端开发必须优先复用现有 H5 工程的“业务层资产”，而不是把全部页面推倒重写。

优先复用：

- `04-统一后端` 的接口定义与接口路径
- `01-扫码用户端` 和 `02-志愿者填写端` 的 TypeScript 类型
- 老人、用药、量表、二维码、邀请码等业务字段映射
- 现有页面的信息结构与文案
- 现有导出、扫码、验证、角色分流规则
- 现有品牌色板、图标语义、卡片层级和间距体系

### 2. 不要硬搬 H5 平台实现

以下内容不能直接照抄到小程序：

- `react-router-dom`
- `window` / `document`
- 浏览器下载逻辑
- H5 hash 路由
- DOM 复制
- 动态创建 `<a>` 下载文件
- 直接依赖 `import.meta.env` 的环境变量读取

### 3. UI 一致的正确方式

目标不是“复制 H5 JSX”，而是复用：

- 页面层级
- 卡片结构
- 间距体系
- 色板
- 文案
- 图标语义

然后在小程序侧重新实现页面壳、交互容器和平台能力。

### 4. 平台能力重写原则

下面这些能力必须改成小程序实现：

- 扫码：改为 `wx.scanCode`
- 存储：改为 `wx.setStorageSync` / `wx.getStorageSync`
- 文件导出：改为 `downloadFile + openDocument`
- 路由：改为小程序页面跳转和分包
- 登录态恢复：改为小程序生命周期驱动

### 4.1 二维码与入口策略原则

当前项目按“双入口、双码”落地：

- `H5 二维码`：面向任何扫码器或系统相机，打开 `https://` 页面
- `小程序码`：面向微信扫一扫，直达小程序指定页面

当前不采用：

- 普通二维码自动按扫描方式分流到 H5 / 小程序
- 依赖 `URL Scheme / URL Link` 的个人主体拉起方案

参数规划要求：

- H5 码与小程序码最终都要能解析到同一个业务对象
- H5 侧优先透传 `qrToken / elderId / archiveNo`
- 小程序码优先通过 `scene` 或 `page/path` 透传同一标识

### 5. 目录与职责严格分层

- `pages/` 和 `subpackages/`：只做页面编排和交互
- `components/`：只做可复用 UI
- `services/`：只做接口访问和平台调用封装
- `store/`：只做状态
- `utils/`：只做纯工具
- `hooks/`：只做状态编排和复用逻辑

不要把接口、页面跳转、状态更新、格式化工具堆在同一个文件里。

## 页面分流原则

### 首页

- `扫码查看`
- `志愿者 / 家属登录`

### 扫码流

- 首页点击 `扫码查看` 后调用 `wx.scanCode`
- 或通过实体卡二维码 / 小程序码直接进入 `scan/landing`
- 后续进入：
  - 基础信息
  - 验证
  - 健康档案
  - 用药信息
  - 量表摘要
  - 名牌导出

### 志愿者 / 家属流

- 统一登录页
- 登录后后端返回角色
- `VOLUNTEER` 进入工作台
- `FAMILY` 进入工作台，但只展示家属权限范围内页面和操作

## 与现有工程的映射关系

- `01-扫码用户端` -> `src/subpackages/scan`
- `02-志愿者填写端` -> `src/subpackages/workbench`
