# 统一后端开发规划

## 1. 当前目标

统一后端为全系统提供唯一业务 API，当前服务对象是：

- 扫码用户端
- 统一照护工作台
  - 志愿者账号模式
  - 家属账号模式
- 管理后台
- 安卓短信中转端

## 2. 当前结构口径

前端已经不再保留独立家属端工程。当前正确口径是：

- 一套统一照护工作台前端
- 两类账号入口
  - 志愿者账号
  - 家属账号

但后端仍然需要分别保留：

- `module/volunteer`
- `module/family`
- `module/invitation`

原因是账号体系、权限判断和数据范围不同，不能因为前端合并就混为一套接口权限。

## 3. 主要模块边界

### `module/scan`

- 扫码解析
- 基础信息返回
- 敏感信息前置验证

### `module/volunteer`

- 志愿者登录
- 本人负责老人列表
- 志愿者业务动作入口

### `module/family`

- 家属登录
- 绑定老人列表
- 联系人维护
- 家属可维护的用药能力

### `module/invitation`

- 邀请码生成
- 邀请码预览
- 邀请码注册绑定

### `module/elder`

- 老人基础档案
- 健康档案
- 用药
- 量表

### `module/qrcode`

- 每位老人唯一二维码
- 扫码链接生成、停用、重新生成

### `module/sms`

- 短信验证领域规则
- 会话、时效、短时授权

### `module/smsrelay`

- 安卓中转设备回传入口
- 心跳上报
- 设备配置下发
- 中转记录入库 / 审计
- 验证会话持久化
- 严格设备密钥校验

### `module/admin`

- 后台统计
- 老人档案、二维码、志愿者、邀请码管理

### `module/audit`

- 管理员、医护/志愿者、访问用户日志分栏
- 导出

### `module/rbac`

- 后台角色说明与权限边界

## 4. 当前正式验证链路

```text
扫码端 / 统一照护工作台
  -> 发起敏感信息查看
  -> 后端创建短信验证会话
  -> 用户向固定号码发送验证码短信
  -> 安卓短信中转端接收并回传
  -> module/smsrelay 入库并转交校验
  -> module/sms 完成会话匹配和放行
  -> 返回敏感数据并记录审计日志
```

## 5. 当前验收重点

- 前端虽然合并，但账号权限不能混
- 家属与志愿者的数据范围必须严格分离
- 短信回传链路必须可以独立留痕
- `smsrelay` 必须能服务扫码端和统一照护工作台

## 6. 当前已完成更新

- `smsrelay` 已从内存态记录改为数据库持久化
- 设备默认配置已支持初始化入库
- 扫码验证会话已支持持久化和过期状态回写
- 未知设备、缺失密钥、错误密钥现在都会被直接拒绝
- `/api/sms-relay/admin/**` 已纳入登录鉴权范围
