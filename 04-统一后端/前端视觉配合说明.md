# 统一后端与前端 UI 复刻配合说明

## 1. 目标

统一后端虽然不直接渲染 UI，但必须提供能支撑三端复刻概念图的数据结构和状态字段。前端 UI 复刻不是只靠样式，后端返回的数据也必须能支持页面上的安全提示、脱敏展示、验证状态、二维码状态和操作日志。

## 2. 扫码用户端需要的后端字段

### 基础信息响应

`POST /api/scan/resolve` 需要返回：

- `archiveNo`：健康档案编号。
- `name`：老人姓名。
- `gender`：性别。
- `age`：年龄。
- `emergencyContactName`：紧急联系人姓名。
- `emergencyPhoneMasked`：脱敏联系电话。
- `relationship`：联系人关系。
- `aboType`：ABO 血型。
- `rhType`：Rh 血型。
- `allergySummary`：过敏史摘要。
- `requiresVerification`：查看敏感档案是否需要二次验证。
- `qrStatus`：二维码状态。

### 敏感档案响应

验证后接口需要返回：

- `verifiedAt`：验证通过时间。
- `verificationMethod`：短信验证码。
- `healthRecord`：健康档案。
- `medications`：主要用药。
- `scaleSummaries`：量表摘要。
- `diagnosisDisclaimer`：量表记录非诊断提示。

## 3. 志愿者端需要的后端字段

### 本人负责老人列表

`GET /api/volunteer/me/elders` 需要返回：

- `elderId`。
- `archiveNo`。
- `name`。
- `age`。
- `lastVisitDate`。
- `status`：待随访、已完成、需复核。
- `scopeHint`：仅显示本人负责老人。

### 表单提交响应

提交接口需要返回：

- `recordId`。
- `submittedAt`。
- `operatorName`。
- `auditLogId`。
- `requiresSmsVerification`。

## 4. 管理后台端需要的后端字段

### 首页统计

`GET /api/admin/dashboard` 需要返回：

- 老人档案总数。
- 志愿者人数。
- 今日扫码次数。
- 今日短信验证通过次数。
- 异常访问次数。

### 二维码管理

二维码接口需要返回：

- `qrId`。
- `elderId`。
- `archiveNo`。
- `status`：启用、停用、已重新生成。
- `publicUrl`：二维码访问 URL。
- `qrImageBase64` 或 `qrImageUrl`。
- `encryptedTokenPreview`：只展示 token 前后片段。
- `securityNote`：二维码不包含明文身份和健康信息。

### 操作日志

日志接口需要返回：

- `time`。
- `operator`。
- `role`。
- `action`。
- `target`。
- `sourceIp`。
- `result`。
- `failureReason`。

## 5. 后端配合 UI 的安全要求

- 后端返回给前端的手机号默认脱敏。
- 前端不负责 AES 解密。
- 二维码 token 只由后端生成和解析。
- 敏感详情接口必须要求短信验证授权。
- 后端必须返回明确状态，方便前端展示“需验证”“已验证”“二维码停用”“权限不足”等 UI。
