## 1. 当前结论

### 已经在代码中落实的重点项

1. 单元测试打出的业务问题
   - `verificationStore.ts` 双定时器竞态
   - 4 个表单页缺少 `catch`
   - `RegisterResultDto.isSuccess()`
   - `AuthProvider` 脏 `sl_user`
   - `ContactManagePage` 告警/保存兜底
   - `MedicationEditorPage` 异常兜底
   - `SimpleTtlCache` 空 key NPE

2. 性能测试打出的高优先级优化
   - `sessionId / recordId` 改 UUID
   - `handleInbound` 从全量扫描改候选匹配
   - 扫码受保护读取聚合缓存
   - `scales` 轻列表 / 重详情拆分
   - 审计异步批量刷写
   - `nameplate pdf` 缓存与资源复用
   - Redis 两级缓存

3. 安全测试打出的高优先级问题
   - `SecurityConfig` 角色路径边界已补齐
   - 跨角色越权已修复并线上复测
   - 更完整防串档已验证错误 `elderId` 返回 `403`
   - 浏览器层 XSS 已验证为文本渲染，不执行联系人字段中的脚本 payload
   - 更深写操作回归已补齐：临时老人 / 邀请码 / 志愿者注册 / 二维码停用审批 / 清理回收链路通过

### 还没有完全落地的项

1. Android Mock/DI 与覆盖率提升
2. `Testcontainers + MySQL` 真执行（代码已建，2026-05-31 实测仍因 `/var/run/docker.sock` 目标缺失而跳过）
3. Playwright / Cypress 级完整浏览器自动化
4. Nginx / 多实例 / Docker 运行时这类环境侧优化
