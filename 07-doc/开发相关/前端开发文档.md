# 前端开发文档

## 1. 项目概述

### 1.1 前端定位

SilverLink Care（智联名牌）项目面向老年护理场景，提供三类前端应用：

- **01-扫码用户端（React H5，Vite）**：面向路人/急救人员，通过扫描二维码查看老人公开信息，验证身份后可查看完整健康档案、用药记录和量表评估结果。内置隐私保护机制（内容防复制、防截屏水印、20分钟验证有效期）。
- **02-志愿者填写端（React Web，Vite）**：面向护理志愿者，提供老人档案维护、健康记录填写、用药管理、量表评估（PHQ-9/GAD-7/UCLA）、二维码管理等功能。同时内嵌 **family-entry 子应用**，面向家属协管账号，支持邀请码注册、老人信息维护、联系人管理、用药管理和二维码查看。
- **03-管理后台端（React Web，Vite）**：面向平台管理员，提供首页数据概览、老人档案管理、志愿者/家属/邀请码管理、二维码管理、用药信息管理、量表记录管理、角色权限控制（RBAC）、操作日志审计、短信中转设备管理等功能。

### 1.2 技术栈选型

| 层级 | 技术选型 | 版本 | 说明 |
|------|----------|------|------|
| 构建工具 | Vite | 7.0+ | 快速开发与生产构建 |
| 框架 | React | 19.0+ | 组件化 UI 开发 |
| 语言 | TypeScript | 5.8+ | 类型安全 |
| 路由 | React Router DOM | 7.15+ | 声明式路由（扫码端 HashRouter，后台 BrowserRouter） |
| 图标 | Lucide React | 0.468+ | 统一图标库 |
| 二维码 | qrcode | 1.5.4 | 二维码生成与解析（志愿者端/后台） |
| 测试 | Vitest + Testing Library | 4.1+ | 单元测试与组件测试 |
| 样式 | CSS 变量 + 原生 CSS | - | 无 UI 框架依赖，轻量可控 |

三个前端项目均不依赖重型 UI 组件库（如 Ant Design、Material UI），全部使用原生 CSS + CSS 变量实现主题与组件样式，保证打包体积最小化。

## 2. 01-扫码用户端

### 2.1 项目概述和定位

扫码用户端是面向公众的 H5 页面，部署在 `/silverlink/scan/` 路径下。用户通过微信/浏览器扫描二维码后进入，首先展示老人的**公开基本信息**（姓名、性别、年龄、紧急联系人等）。涉及隐私的模块（健康档案、用药记录、量表记录）需要经过身份验证后方可查看。

**核心安全机制**：
- 短信验证码验证（对接短信中转设备）
- 身份登记验证（姓名+手机号+身份证）
- 验证有效期 20 分钟，过期自动失效
- 内容保护：防复制、防截屏水印、禁用右键
- 审计日志：所有访问行为上报后端

#### 2.3.2 短信验证页 (/verify)

**功能**：提供两种验证模式，通过后方可查看敏感信息。

**表单字段**：

短信验证模式：
- 目标手机号（只读，来自二维码解析结果）
- 短信验证码（6位数字）
- 发送验证码按钮（60秒倒计时）

身份登记模式：
- 姓名
- 手机号
- 身份证号

**交互逻辑**：
1. 页面加载时解析 URL 中的二维码 token
2. 调用 `/api/scan/resolve` 获取老人公开信息和验证目标手机号
3. 用户选择验证模式（短信/身份登记）
4. 短信模式：点击发送 → 调用 `startRelayVerification` → 输入验证码 → 调用 `checkVerificationStatus`
5. 身份登记模式：填写姓名/手机号/身份证 → 调用 `verifyIdentityAccess`
6. 验证成功后，SecurityProvider 设置 20 分钟有效期，跳转回首页

### 2.5 状态管理

#### 2.5.1 验证状态（SecurityProvider + verificationStore）

```typescript
interface SecurityContextValue {
  verified: boolean;
  verifiedSessionId: string;
  verifiedElderId: string;
  verifiedUntil: number | null;
}

type VerificationStatus = 'none' | 'pending' | 'verified' | 'expired';

interface VerificationStore {
  status: VerificationStatus;
  countdown: number;
  errorCount: number;
  authorizedUntil: number | null;
  lastError: string;
}
```

**核心逻辑**：
- `AUTH_TTL_MS = 20 * 60 * 1000`（20分钟有效期）
- `MAX_ERROR_COUNT = 5`（最多允许5次错误）
- 错误次数达到上限后状态变为 `expired`
- 倒计时使用 `setInterval` 实现秒级更新
- 认证过期使用 `setTimeout` 自动触发

## 3. 02-志愿者填写端

### 3.1 项目概述和定位

志愿者填写端面向护理志愿者，提供完整的老人档案维护工作流。采用**条件渲染**方式切换页面（非路由），保持表单状态连续性。同时内嵌 **family-entry 子应用**，通过 HashRouter 独立运行，面向家属协管账号。

**核心功能**：
- 志愿者登录（账号密码）/ 邀请码注册
- 负责老人列表（轮播卡片式浏览）
- 老人详情与快捷导航
- 基本信息编辑（含短信验真）
- 健康档案填写（身高/体重/BMI/腰围/自评量表）
- 用药记录维护（批量编辑模式）
- 量表评估填写（PHQ-9/GAD-7/UCLA）
- 二维码管理（查看/重新生成/停用）
- 家属协管子应用（邀请码注册、登录、老人管理、联系人维护、用药管理、二维码查看）

### 3.3 页面设计

#### 3.3.1 登录页 (LoginPage)

**功能**：志愿者账号密码登录，或邀请码注册新账号。

**表单字段**：
- 账号
- 密码
- 邀请码（注册模式）

**交互逻辑**：
1. 输入账号密码 → 调用 `loginVolunteer` → 存储 token 和用户信息 → 进入老人列表
2. 或输入邀请码 → 预览邀请信息 → 填写注册信息 → 调用 `registerVolunteer`

#### 3.3.2 老人列表页 (AssignedElderListPage)

**功能**：展示志愿者负责的老人列表，支持轮播卡片式浏览。

**组件结构**：
```
AssignedElderListPage
├── PageHeader (title="我的老人", action=账号管理)
├── SearchBox (搜索姓名/档案编号)
├── ElderCarousel
│   └── ElderCard[] (轮播卡片，含老人头像、姓名、档案编号、年龄、住址、状态)
├── CarouselDots (分页指示器)
└── QuickAction (进入档案/快速维护)
```

**交互逻辑**：
- 左右滑动切换老人卡片
- 点击卡片进入老人详情
- 搜索实时过滤
- 支持新增老人（弹窗表单）

#### 3.3.3 老人详情页 (ElderDetailPage)

**功能**：展示老人概要信息，提供快捷入口到各编辑页面。

**组件结构**：
```
ElderDetailPage
├── PageHeader (title="老人详情", onBack)
├── SummaryHero (姓名、档案编号、性别、年龄)
├── SummaryGrid (住址、紧急联系人、电话、血型/过敏史)
└── ActionGrid
    ├── ActionCard (基本信息)
    ├── ActionCard (健康档案)
    ├── ActionCard (主要用药)
    ├── ActionCard (量表信息)
    └── ActionCard (二维码管理)
```

#### 3.3.4 基本信息编辑页 (BasicInfoFormPage)

**功能**：编辑老人基本信息，含短信验真确认。

**表单字段**：
- 姓名
- 性别（男/女）
- 年龄
- 居住地
- 紧急联系人姓名
- 紧急联系人电话
- 与老人关系
- ABO 血型（A/B/AB/O/其他）
- Rh 血型（阳性/阴性/其他）
- 过敏史

**交互逻辑**：
1. 表单变更后点击保存
2. 弹出短信验证确认（向紧急联系人手机发送验证码）
3. 验证通过后调用 `saveBasicInfo`

#### 3.3.5 健康档案填写页 (HealthRecordFormPage)

**功能**：填写老人健康指标和自评量表。

**表单字段**：
- 身高（cm）
- 体重（kg）
- 腰围（cm）
- BMI（自动计算，只读）
- 自评健康状况（很好/较好/一般/较差/很差）
- 生活自理能力（完全自理/部分自理/不能自理）
- 认知功能筛查（正常/可疑/异常）
- 情绪状态筛查（无明显异常/轻度/中度/重度）

**交互逻辑**：
- 身高体重变更时自动计算 BMI
- 使用 `SelectChips` 组件进行单选

#### 3.3.6 用药记录编辑页 (MedicationFormPage)

**功能**：维护老人用药清单，支持批量编辑模式。

**组件结构**：
```
MedicationFormPage
├── PageHeader
├── MedicationTable
│   ├── TableHeader (药品名称/剂量/用法/用药时间/操作)
│   └── TableRow[]
└── ActionBar (添加用药/保存)
```

**交互逻辑**：
- 点击添加用药 → 弹出模态框编辑
- 支持编辑和删除单条用药
- 批量模式下所有变更在客户端暂存，点击保存后统一提交

#### 3.3.7 量表填写页 (ScaleFormPage)

**功能**：填写 PHQ-9、GAD-7 或 UCLA 量表。

**组件结构**：
```
ScaleFormPage
├── PageHeader (title="量表填写", subtitle=量表类型)
├── ScaleInfo (量表说明)
└── ScaleQuestion[]
    ├── QuestionText
    └── OptionChips (0-3 分选项)
```

**量表题目来源**（`data/scaleQuestions.ts`）：
- PHQ-9：9 道题，评估抑郁症状
- GAD-7：7 道题，评估焦虑症状
- UCLA：20 道题，评估孤独感（含反向计分题）

**交互逻辑**：
- 每道题使用 0-3 分四级评分
- 全部题目回答后自动计算总分
- 提交后保存到后端

#### 3.3.8 二维码管理页 (QrCodeManagePage)

**功能**：查看、重新生成、停用老人的二维码。

**交互逻辑**：
- 查看当前二维码状态
- 重新生成二维码（旧二维码失效）
- 申请停用二维码（需管理员审核）

## 4. 03-管理后台端

### 4.1 项目概述和定位

管理后台端面向平台管理员，提供完整的业务数据管理和系统配置功能。采用 **BrowserRouter** 路由，左侧边栏导航，支持 RBAC 角色权限控制。

**核心功能**：
- 首页数据概览（老人、志愿者、二维码、日志等多维度统计）
- 老人档案管理（增删改查、状态切换、CSV 导出）
- 用药信息管理（全局列表、单老人内联编辑、CSV 导出）
- 量表记录管理（按老人聚合、CSV 导出）
- 二维码管理（查看、停用、重新生成、绑定短信中转设备）
- 志愿者管理（增删改查、负责老人分配、CSV 导出）
- 家属绑定管理（查看绑定关系、解绑）
- 邀请码管理（创建、复制、作废、重新生成）
- 角色权限管理（RBAC 矩阵、账号类型变更）
- 操作日志审计（多分类筛选、 visitor 专属分析面板、CSV 导出）
- 短信中转管理（设备管理、记录查看、会话查看）

### 4.6 API 调用

#### 4.6.1 HTTP 客户端（adminApi.ts）

**安全特性**：
- **HMAC-SHA256 请求签名**：每个请求携带 `X-Timestamp`、`X-Nonce`、`X-Signature`
- **签名算法**：
  ```
  canonical = METHOD + "\n" + path + "\n" + timestamp + "\n" + nonce
  signature = HMAC-SHA256(secret, canonical)
  ```
- **前端缓存**：GET 请求 15 秒 TTL，避免重复请求
- **请求去重**：相同 GET 请求在 pending 状态下共享 Promise
- **401/403 自动登出**：清除 session 并触发事件

```typescript
const GET_CACHE_TTL_MS = 15_000;
const responseCache = new Map<string, { expiresAt: number; data: unknown }>();
const pendingGetRequests = new Map<string, Promise<unknown>>();

async function request<T>(path: string, options?: RequestInit): Promise<T>
export function invalidateAdminCache(): void
```

## 5. 跨项目共享规范

### 5.1 代码风格

- 使用 TypeScript 严格模式
- 组件使用函数式组件 + Hooks
- Props 接口使用 `interface` 定义
- 事件处理函数使用 `handleXxx` 命名
- 布尔状态使用 `isXxx` / `hasXxx` / `showXxx` 命名

### 5.2 错误处理

- API 错误统一抛出 `Error` 实例
- 页面级错误使用 `try/catch` + `setError` 状态
- 表单校验错误在提交前检查，阻止提交

### 5.3 性能优化

- 使用 `useMemo` 缓存计算结果（过滤、分组、统计）
- 使用 `useCallback` 缓存事件处理函数
- 大数据列表使用虚拟滚动（如需要）
- 后台 GET 请求使用 15 秒缓存

### 5.4 安全规范

- 敏感信息（手机号、身份证号）必须脱敏展示
- 前端权限控制仅用于 UI 展示，不替代后端校验
- 管理后台 API 请求必须携带 HMAC-SHA256 签名
- 扫码端内容保护组件防止信息泄露
- 所有访问行为记录审计日志
