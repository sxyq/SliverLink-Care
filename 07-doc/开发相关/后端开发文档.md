## 1. 项目概述

### 1.1 后端定位

SilverLink Care 后端为智联名牌项目提供统一的 RESTful API 服务，支撑三大前端端（扫码用户端、志愿者填写端、管理后台端）及 Android SMS Relay 短信中转设备的全部业务交互。核心职责包括：

- **RESTful API 服务**：老人档案、扫码查看、志愿者管理、家属协管、邀请码注册、二维码管理、短信验证、审计日志等核心业务接口
- **数据持久化**：MySQL 数据库存储，Flyway 版本化迁移管理
- **安全体系**：JWT 无状态认证、AES-GCM 字段级加密、HMAC-SHA256 请求签名、RBAC 权限模型
- **短信中继集成**：与 Android SMS Relay 设备协同完成扫码用户的短信验证码中转验证
- **名牌导出**：基于 PDFBox 的矢量名牌 PDF 生成与二维码渲染

## 3. 各模块详细说明

### 3.1 扫码用户模块 (scan)

**定位**：供路人/急救人员扫描老人名牌二维码后查看脱敏信息，以及通过短信中继或实名认证完成身份验证后查看完整档案。

#### ScanController

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /api/scan/resolve | 解析二维码 token，返回老人脱敏基础信息 |
| POST | /api/scan/auth/wechat | 微信登录，解析 code 获取 openid |
| POST | /api/scan/verification/start | 启动短信中继验证会话 |
| GET | /api/scan/verification/status | 查询验证会话状态 |
| POST | /api/scan/verification/identity | 实名认证验证（姓名+手机+身份证） |
| GET | /api/scan/archive | 验证通过后查看健康档案 |
| GET | /api/scan/basic-info | 验证通过后查看完整基础信息 |
| GET | /api/scan/medications | 验证通过后查看用药记录 |
| GET | /api/scan/scales | 验证通过后查看量表记录 |

#### ScanService

- `resolve(String token)`：调用 QrCodeService 解密并校验 token，返回老人脱敏信息
- `startVerificationSession(elderId, target)`：创建短信中继验证会话，生成随机消息体
- `getVerificationStatus(sessionId)`：查询会话状态
- `verifyByIdentity(...)`：创建实名认证验证会话，直接标记为 VERIFIED
- `authorizeSession(sessionId, elderId, target)`：调用 SmsRelayService 校验会话有效性
- `getArchiveData / getVerifiedBasicInfoData / getMedicationsData / getScalesData`：透传数据查询

#### WeChatAuthService

## 4. 核心功能模块

### 4.1 认证模块

#### JwtTokenProvider

- `generateToken(subject, role, ttlMillis)`：使用 HS256 签名生成 JWT，payload 包含 subject（账号）和 role
- `parseToken(token)`：解析并验证签名，返回 Claims
- `validateToken(token)`：解析是否成功
- `getSubject(token)` / `getRole(token)`：提取账号与角色

#### JwtAuthenticationFilter

继承 `OncePerRequestFilter`，在每个请求中：
1. 读取 `Authorization` 头，提取 `Bearer ` 后的 token
2. 调用 `JwtTokenProvider.validateToken()` 验证
3. 验证通过后，构造 `UsernamePasswordAuthenticationToken`，设置 `ROLE_` 前缀的权限，写入 `SecurityContextHolder`
4. 异常或无效 token 时继续过滤器链，不阻断（由后续授权配置决定）

### 4.2 安全配置 (SecurityConfig)

```java
@Bean
public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
    http
        .csrf(csrf -> csrf.disable())
        .sessionManagement(sm -> sm.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
        .authorizeHttpRequests(auth -> auth
            .requestMatchers(
                "/api/scan/**",
                "/api/sms/**",
                "/api/sms-relay/inbound",
                "/api/sms-relay/heartbeat",
                "/api/sms-relay/devices/*/config",
                "/api/nameplates/**",
                "/api/audit-logs/report",
                "/api/admin/login",
                "/api/volunteer/login",
                "/api/volunteer/register",
                "/api/invitations/**",
                "/api/family/login"
            ).permitAll()
            .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
            .requestMatchers(
                "/api/admin/**",
                "/api/volunteer/me/**",
                "/api/elder/**",
                "/api/rbac/**",
                "/api/audit-logs/**",
                "/api/family/**",
                "/api/sms-relay/admin/**"
            ).authenticated()
            .anyRequest().permitAll()
        )
        .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class)
        .httpBasic(basic -> basic.disable())
        .formLogin(fl -> fl.disable());
    return http.build();
}
```

**开放接口**：扫码、短信、短信中继设备端、名牌预览/下载、审计上报、登录注册、邀请码相关。
**认证接口**：管理员后台、志愿者个人中心、老人档案填写、RBAC、审计日志查询、家属端、短信中继管理后台。

### 4.3 数据范围隔离 (DataScopeInterceptor)

当前 Demo 阶段为占位实现，正式版将对接 MyBatis-Plus 拦截器，基于 `RbacPermissionEvaluator.canAccessDataScope()` 实现 SQL 级别的数据范围过滤。当前的数据隔离通过 `SilverLinkDataService.requireVolunteerScope(elderId)` 在业务层实现：从 SecurityContext 获取当前认证信息，若为志愿者角色，则检查 `volunteer_elder_scope` 表中是否存在该志愿者与目标老人的关联记录，不存在则抛出 `BizException(403)`。

### 4.4 AES-GCM 加密服务 (AesGcmCryptoService)

- **算法**：AES/GCM/NoPadding，IV 长度 12 字节，认证标签 128 位
- **密钥管理**：通过 `silverlink.security.aes-key-base64` 配置 Base64 编码的 AES 密钥，`aes-key-id` 标识密钥版本
- **密文格式**：`{keyId}.{base64url(iv || ciphertext)}`
- `encrypt(plaintext)`：生成随机 IV → GCM 加密 → Base64URL 编码 → 拼接 keyId
- `decrypt(token)`：分离 keyId → Base64URL 解码 → 提取 IV 和密文 → GCM 解密

**加密字段覆盖**：`app_user.name_enc/phone_enc`、`elder.name_enc/residence_enc/emergency_contact_name_enc/emergency_phone_enc/backup_contact_name_enc/backup_phone_enc/allergy_enc`、`medication.name_enc/dosage_enc/usage_text_enc/timing_enc`、`scale_record.payload_enc`、`family_binding.family_name_enc/family_phone_enc`、`audit_log.visitor_name_enc/visitor_phone_enc/visitor_id_card_enc`、`scan_verification_session.visitor_name_enc/visitor_phone_enc/visitor_id_card_enc`

**启动自动加密**：`SilverLinkDataService.encryptSeedData()` 在 `@PostConstruct` 中扫描上述所有字段，若值为明文则自动加密，确保历史数据兼容。

### 4.5 审计日志记录

`SilverLinkDataService.recordAudit(...)` 提供 12 参数完整版与 8 参数简版，写入 `audit_log` 表。所有 Controller 的关键操作（登录、登出、查看档案、修改数据、生成/停用二维码、发送短信、验证身份等）均调用 `AuditLogService.record(...)` 留痕。访客扫码查看档案时，记录访客姓名、手机、身份证（实名认证场景）及验证方式。

## 8. 与 Android SMS Relay 集成

### 8.1 集成架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Android SMS Relay 设备                    │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │ SMS Receiver│───→│ Message     │───→│ HTTP Uploader│    │
│  │ (系统广播)   │    │ Matcher     │    │ (带签名)      │    │
│  └─────────────┘    └─────────────┘    └─────────────┘     │
└──────────────────────────┬──────────────────────────────────┘
                           │ POST /api/sms-relay/inbound
                           │ (X-Relay-Device-Secret / Timestamp / Nonce / Signature)
                           ▼
┌─────────────────────────────────────────────────────────────┐
│              SilverLink Care Backend                        │
│  ┌─────────────────────────────────────────────────────┐   │
│  │ SmsRelayController / SmsRelayService                │   │
│  │  - validateDeviceRequestSignature()                 │   │
│  │  - handleInbound() → 匹配 scan_verification_session │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 设备认证机制

Android 设备每次请求携带四个头部：
- `X-Relay-Device-Secret`：设备预共享密钥
- `X-Relay-Timestamp`：Unix 时间戳（秒）
- `X-Relay-Nonce`：随机字符串，防重放
- `X-Relay-Signature`：HMAC-SHA256 签名

**签名原文**：`METHOD\nrequestUri\ntimestamp\nnonce\npayload`

服务端 `SmsRelayService.validateDeviceRequestSignature()` 执行：
1. 校验设备存在且 secret 匹配
2. 校验时间戳在 `signatureWindowSeconds`（默认 300 秒）内
3. 校验 nonce 未使用过（内存 ConcurrentHashMap 池，定期清理过期项）
4. 重新计算 HMAC-SHA256 并与请求签名做常量时间比较

### 8.3 验证流程

1. **扫码用户**扫描名牌 → 后端 `ScanController.resolve()` 返回老人脱敏信息
2. 用户点击"查看完整档案" → 后端 `ScanController.startVerification()` 创建 PENDING 会话，返回 `messageBody`（如 `SL AB3CD9EF2K`）
3. 用户用**自己的手机**向短信中转设备号码发送该消息体
4. **Android 设备**收到短信后，通过 `POST /api/sms-relay/inbound` 将短信内容回传后端
5. 后端 `handleInbound()` 匹配 `scan_verification_session` 中 PENDING 且 `message_body` 与 `receiver_phone` 均一致的会话，将其标记为 VERIFIED
6. 扫码用户轮询 `GET /api/scan/verification/status`，状态变为 VERIFIED 后即可访问完整档案

### 8.4 实名认证备选流程

若用户无法使用短信中继，可通过 `POST /api/scan/verification/identity` 提交姓名、手机号、身份证号，后端直接创建 VERIFIED 会话，无需等待短信回传。身份证号执行格式校验与大陆 18 位身份证校验码验证。

### 8.5 设备管理

- `ensureDefaultDevice()`：`@PostConstruct` 时若数据库无设备，自动插入默认设备（deviceId=`relay-android-01`，secret=`secret-001`）
- 管理员可通过 `/api/sms-relay/admin/devices` 查看设备状态（在线/离线）
- 可通过 `/api/sms-relay/admin/devices/{id}` 修改接收手机号、服务器地址、消息前缀

## 9. 异常处理

### 9.1 BizException

业务异常，携带 `code` 与 `message`：
- 400：参数错误、业务规则校验失败
- 401：未认证、Token 无效、验证会话过期
- 403：无权访问（数据范围越界、绑定关系不存在）
- 404：数据不存在
- 429：短信发送过于频繁
- 500：服务器内部错误
- 502：微信认证网关错误

### 9.2 GlobalExceptionHandler

- `@ExceptionHandler(BizException.class)`：根据 code 映射 HTTP 状态码，包装为 `ApiResponse.fail(code, message)`
- `@ExceptionHandler(Exception.class)`：返回 500，包装异常消息
