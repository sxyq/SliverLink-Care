# 汇总

## 1. 项目概述
### 1.1 项目名称与定位
智联名牌（SilverLink Care）是一个围绕老人实体名牌、扫码访问、统一照护工作台、管理后台和安卓短信中转端构成的社区养老协同系统。

### 1.2 建设背景
项目面向社区养老、志愿服务和家属协同照护场景，希望把原本分散的纸质记录、电话沟通和线下核验流程，收敛为一个可追踪、可验证、可审计的数字化链路。

### 1.3 核心目标
- 让老人基础救助信息可以通过实体名牌快速获取。
- 让敏感健康信息在验证通过后才可访问。
- 让志愿者、家属和管理员围绕同一份老人档案协同工作。
- 让关键操作全过程留痕，便于后续复核与审计。

### 1.4 当前版本范围
当前版本已经覆盖三端一后台一安卓端：
- 扫码用户端
- 统一照护工作台中的志愿者账号入口
- 统一照护工作台中的家属账号入口
- 管理后台
- 统一后端
- 安卓短信中转端

### 1.5 三端一后台一安卓端关系说明
- 扫码用户端面向外部扫码访问者，承担“公开信息展示 + 敏感信息验证后查看”。
- 统一照护工作台面向志愿者与家属，承担“老人协同维护”。
- 管理后台面向管理员与审计人员，承担“档案、二维码、账号、权限、日志与设备管理”。
- 安卓短信中转端承担“固定号码短信接收、解析和安全回传”。
- 统一后端提供统一的数据、权限、验证与审计能力。

### 1.6 当前发布状态（2026-08-17）
- 三语词条、RTL 布局和语言切换已接入扫码 H5、统一照护工作台与微信小程序；Web 端语言入口固定在物理右上角。
- 微信小程序开发版本已上传，320×568、390×844、768×1024 三种尺寸下的三语言页面矩阵已完成验证。开发版上传不等同于微信公众平台正式发布。
- 志愿者端线上静态资源已按 `/silverlink/volunteer/` 子路径发布，语言切换按钮与三语菜单已在公网重新核验。
- 当前家属协管入口仍使用独立认证与家属绑定数据模型。已确认的产品目标是志愿者与家属协管共用账号和登录入口，由入口标签决定功能范围；由于现有绑定数据尚未指定迁移到哪个统一账号，本轮保持代码和线上数据不变。

## 2. 系统组成总览
### 2.1 扫码用户端
扫码用户端运行于移动端 H5，当前以微信内浏览器访问为主要使用形态。其核心能力包括二维码解析、基础信息展示、身份登记、短信验证、健康档案查看、主要用药查看和量表记录查看。

### 2.2 统一照护工作台
统一照护工作台是一个前端工程，包含两类入口：
- 志愿者账号入口
- 家属协管入口

两类入口共用老人工作台页面骨架，只在功能与数据权限上区分。当前实现仍保留独立家属认证；统一账号登录模型已确认，待明确现有家属绑定迁移到哪个账号后再实施。

### 2.3 管理后台
管理后台负责老人档案管理、用药与量表管理、二维码管理、志愿者与家属关系管理、邀请码管理、短信中转设备管理、角色权限管理和审计日志管理。

### 2.4 统一后端
统一后端是唯一服务端，当前基于 Spring Boot 实现，统一支撑扫码端、工作台、后台和安卓端，并负责二维码解析、身份验证、短信验证会话、安全校验和数据持久化。

### 2.5 安卓短信中转端
安卓短信中转端是正式业务链路的一部分，用于绑定固定接收手机号、接收验证码短信、解析内容、生成签名并回传后端，同时定时上报设备心跳和在线状态。

## 3. 核心业务总览
### 3.1 老人健康档案管理
管理员创建老人档案并维护基础资料，志愿者和家属在权限范围内补充和查看对应老人相关信息。

### 3.2 家属与志愿者协同
志愿者主要负责随访、健康信息录入和量表填写；家属主要负责联系人维护、用药维护和二维码查看。双方围绕同一老人档案协同，但能力范围不同。

### 3.3 二维码生成与扫码查看
后台为老人生成唯一二维码，绑定到具体老人档案。扫码后先展示基础救助信息，敏感健康信息需要进入验证流程后才可访问。

### 3.4 身份验证与短信验证
扫码用户需要先提交姓名、手机号、身份证号等身份信息，再通过固定号码短信回传验证完成二次核验。只有验证成功后，系统才发放访问敏感页面的短时权限。

### 3.5 用药信息与量表记录
系统支持维护用药信息和量表记录，并在不同端按不同口径展示：
- 扫码端展示验证后可见的摘要或详情
- 工作台用于录入与维护
- 后台用于管理和追溯

### 3.6 审计日志与操作追踪
后台记录管理员操作日志，同时区分管理员操作、医护/志愿者操作、家属操作和访客访问记录，形成全链路追踪能力。
