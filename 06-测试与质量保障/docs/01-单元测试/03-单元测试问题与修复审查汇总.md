## 二、审查方法

1. 逐条从每份 regression 记录中抽取问题、模块、源码文件、问题类型、原始证据
2. 回到源码文件逐行核对当前状态，判断属于：已修复 / 部分修复 / 未修复 / 无法确认
3. 明确区分"业务 bug"和"测试基础设施问题"和"工具链/环境噪音"
4. 对"部分修复"记录还差什么、是否影响业务、是否影响继续补测
