# 非单元测试剩余规划

## 1. 目标

本文件基于当前已完成的测试进度，规划后续“非单元测试”部分的落地范围、执行顺序、阻塞条件与验收标准。

这里的“非单元测试”包括：

- 功能测试
- 集成测试
- 安全与权限测试
- 性能测试
- E2E / 浏览器交互测试
- Android 仪器测试
- 部署前回归测试

不包含函数级、组件级、service 级单元测试。

## 2. 当前进度结论

根据已有报告，当前非单元测试状态如下：

| 类别 | 当前状态 | 结论 |
| --- | --- | --- |
| 功能烟测 | 已执行线上只读入口烟测 | 已有基础可用性证据，但未覆盖真实业务交互 |
| 集成测试入口 | 已执行后端 `mvn test jacoco:report` 聚合入口 | 已跑通，但还不是真正的多模块数据库集成场景 |
| 安全负例烟测 | 已执行缺 token、错 token、缺签名等负例 | 已有基础负例证据，但还缺深专项 |
| 性能采样 | 已执行轻量延迟采样 | 已有首页和基础接口延迟基线，但还没形成全链路性能专项 |
| E2E | 已有只读入口 fallback 烟测 | 还没有真实 Playwright 浏览器交互流 |
| Android 仪器测试 | 已尝试执行 | 因无设备/模拟器阻塞 |
| 回归测试 | 已有项目级全量回归入口 | 已能执行 build/test 聚合，但业务回归矩阵还未系统化 |

## 4. 剩余工作拆分

### 4.1 功能测试

#### 已完成

- 三个线上入口可达性只读验证

#### 剩余重点

##### 扫码端

- 有效二维码进入基础信息页
- 非法二维码进入错误页
- 身份证错误时提示身份证错误，不误报手机号
- 手机号错误时提示手机号错误
- 验证成功后显示当前二维码对应老人
- 不同二维码之间验证状态不能串用
- 健康档案、基础信息、用药、量表四个受保护页面访问控制

##### 志愿者/家属端

- 邀请码注册成功后自动登录
- 邀请码错误、过期、次数耗尽提示
- 志愿者查看老人二维码、复制、重新生成
- 家属绑定老人成功与失败流
- 家属短信验证切换主手机号/备用手机号后的行为

##### 管理后台

- 登录与登出
- 老人档案新增、编辑、停用
- 二维码弹窗复制链接与打开扫码页
- 后台表格在桌面、平板、窄屏下操作列可见
- 审计日志筛选、导出
- RBAC 页面角色变更与失败提示

##### Android 短信端

- 启动服务
- 配置保存
- 收到匹配短信后触发上传
- 心跳发送
- 上传失败后重试

## 5. 推荐执行顺序

建议后续按下面顺序推进非单元测试：

1. 真实浏览器 E2E 基础能力打通
2. 功能测试 P0 业务链路
3. 安全专项中的防串档与权限边界
4. Testcontainers 数据库集成场景
5. 性能专项
6. Android 仪器测试
7. 固化部署前回归矩阵

原因：

- 真实浏览器 E2E 是功能与 UI 行为验证的基础能力。
- 防串档、跨角色访问、扫码链路属于项目最高风险点。
- 性能和 Android instrumentation 更依赖环境准备，排在中后段更稳。

## 6. 分阶段执行计划

### 阶段 A：补齐浏览器级与功能级证据

目标：

- 不再只停留在入口只读烟测
- 拿到真实点击、输入、路由跳转、弹窗、响应式证据

输出物：

- `reports/e2e/<timestamp>-playwright-.../`
- `reports/functional/<timestamp>-interactive-.../`
- 截图与失败复现说明

### 阶段 B：补齐后端深集成与安全专项

目标：

- 把“只读 API 基础验证”升级为“真实会话、防串档、防越权、数据库状态”的深验证

输出物：

- `reports/integration/<timestamp>-testcontainers-.../`
- `reports/security/<timestamp>-deep-security-.../`

### 阶段 C：补齐性能专项

目标：

- 从单接口轻量延迟采样，升级到核心链路和关键资产性能基线

输出物：

- `reports/performance/<timestamp>-scan-chain-...json`
- `reports/performance/<timestamp>-admin-api-...json`
- `reports/performance/<timestamp>-pdf-...json`

### 阶段 D：补齐 Android 仪器测试

目标：

- 在设备或模拟器环境下验证短信中转端的真实系统行为

输出物：

- `reports/regression/<timestamp>-android-instrumentation-...md`
- 截图、logcat、失败说明

### 阶段 E：固定部署前回归门禁

目标：

- 建立历史 bug 回归矩阵
- 让每次部署前的检查有固定清单

输出物：

- `docs/06-回归测试/README.md` 后续补充矩阵
- `reports/regression/<timestamp>-pre-deploy-gate-.../`

## 7. 当前阻塞与依赖

### Playwright E2E 阻塞

- 当前只有 fallback 只读烟测
- 需要可用的真实浏览器执行入口

### Android 仪器测试阻塞

- 当前没有连接设备或模拟器
- 需要 `adb` 和可用 target

### Testcontainers 集成测试阻塞

- 当前仓库还没有真实 `@Testcontainers / MySQLContainer` 用例
- 需要补测试实现与容器运行条件

### Android 覆盖率聚合阻塞

- Android JVM 单测已经能跑
- 但统一汇总脚本尚未接入 Android JaCoCo XML 聚合

## 8. 验收标准

非单元测试部分后续至少要达到：

### 功能

- 三端核心 P0 流程全部有真实交互型证据

### 集成

- 二维码 -> 验证 -> 受保护读取 -> 审计日志 形成可重复执行链路

### 安全

- 防串档、跨角色、错签名、重放、过期等核心场景均有明确通过/失败断言

### 性能

- 至少覆盖首页、扫码链路、后台核心接口、PDF 生成
- 输出 P50 / P95 / P99

### Android

- JVM 单测继续保持通过
- 至少一次真机或模拟器 instrumentation 成功执行

### 回归

- 历史关键 bug 有固定回归矩阵并可重复执行

## 9. 后续实施建议

如果下一步优先推进非单元测试，建议按照下面两个任务包先做：

1. 真实 Playwright E2E + 功能 P0 流程
2. 安全专项 + Testcontainers 集成链路

这是当前收益最高、也最能补齐“单元测试之外真实质量证据”的两块。
