# 测试总规划

## 1. 测试目标

本目录用于建立智联名牌项目的长期质量保障体系，覆盖功能、单元、集成、性能、安全权限和回归测试。测试资料、脚本、报告统一放在 `06-测试与质量保障/`，避免散落在各端工程里。

## 2. 分类目录

| 分类 | 文档目录 | 脚本目录 | 报告目录 | 目标 |
| --- | --- | --- | --- | --- |
| 总览 | `docs/00-总览` | `scripts/common` | `reports/` | 测试基线、执行顺序、报告规范 |
| 单元测试 | `docs/01-单元测试` | `scripts/unit` | `reports/unit` | 每个函数/方法/组件行为的最小粒度验证 |
| 功能测试 | `docs/02-功能测试` | `scripts/functional` | `reports/functional` | 三端页面和主要业务流程可用 |
| 集成测试 | `docs/03-集成测试` | `scripts/integration` | `reports/integration` | 前端、后端、数据库、短信中转串联正确 |
| 性能测试 | `docs/04-性能测试` | `scripts/performance` | `reports/performance` | 页面、接口、构建产物、PDF 生成性能基线 |
| 安全与权限测试 | `docs/05-安全与权限测试` | `scripts/security` | `reports/security` | 权限、隐私、签名、防串档、防越权 |
| 回归测试 | `docs/06-回归测试` | `scripts/regression` | `reports/regression` | 每次修复和部署前的稳定性确认 |

## 4. 第一轮推荐执行顺序

1. 固定测试基线：记录 Git commit、工作区状态、服务地址、数据库环境。
2. 单元测试规划落地：先补工具函数、API 映射函数、后端 service、安卓 util 的单元测试。
3. 构建门禁：三个前端 `npm run build`，后端 Maven 测试/打包，安卓 JVM 测试/构建。
4. 功能冒烟：扫码端、志愿者/家属端、管理后台核心页面逐个打开和交互。
5. 专项回归：近期修复的扫码错人、二维码按钮、邀请码注册、后台表格展示。
6. 集成测试：二维码解析到验证再到受保护档案读取的完整链路。
7. 性能基线：构建体积、页面加载、关键接口响应、PDF 生成耗时。
8. 生成报告：每轮输出 `summary.md`、`failures.md`、`commands.log`、截图和性能数据。

## 5. 报告规范

每轮测试报告建议使用：

```text
06-测试与质量保障/reports/<分类>/YYYYMMDD-HHMM-测试主题/
```

每轮至少包含：

- `summary.md`: 总结、结论、风险。
- `commands.log`: 关键命令、退出码、日志摘要。
- `failures.md`: 失败项、复现步骤、相关文件、建议修复。
- `screenshots/`: 前端和移动端截图证据。
- `performance.json`: 性能指标。

## 6. 当前已知风险

- 管理后台 `admin-layout.css` 曾出现 CSS 结构损坏，后台 UI 测试前应先确认构建无 CSS 语法警告。
- 前端当前没有单元测试脚本，需先引入 Vitest + Testing Library，才能执行函数级单元测试。
- 安卓仪器测试依赖模拟器或真机，应与 JVM 单元测试分开执行。
- 当前工作区存在非本测试目录的未提交/删除状态，正式测试前需要明确是否纳入本轮基线。
